    API reference¶

    This reference is generated from the docstrings in the source code, so it always matches the installed version. Everything below can be imported from the top-level package:

    from mifarepy import (
    MifareReader, SectorAuth, CardInfo,
    GNetPlusError, InvalidMessage,
    QueryMessage, ResponseMessage, Message, gencrc,
)

    Reader¶

    MifareReader ¶

    MifareReader(port: str = '/dev/ttyUSB0', baudrate: int = 19200, deviceaddr: int = 0, *, value_ops: ValueOps = 'auto', **kwargs: Any)

    Class for interfacing with the RFID card reader.

    Can be used as a context manager to ensure the serial port is closed:

    with MifareReader('/dev/ttyUSB0') as reader:
    uid = reader.get_sn()

    Initialize the RFID reader connection.

    Parameters:

    Name Type Description Default
    port str

    Serial port name (e.g., '/dev/ttyUSB0').

    		 '/dev/ttyUSB0'
    baudrate int

    Baudrate for interfacing with the device. Don't change this unless you know what you're doing.

    		 19200
    deviceaddr int

    Device address (default: 0).

    		 0
    value_ops ValueOps

    How value-block arithmetic is performed. 'auto' (default) increments and decrements by read-modify-write, and uses the native RESTORE / TRANSFER commands for transfer() / restore(), verifying the result and falling back to read-modify-write if they fail. 'native' uses only the native commands, including SET_VALUE for increment/decrement; 'software' uses only read-modify-write (the behaviour before 3.1).

    		 'auto'
    **kwargs Any

    Extra keyword arguments passed to serial.Serial.

    		 {}

    Raises:

    Type Description
    RuntimeError

    If the serial port cannot be opened.

    close ¶

    close() -> None

    Reset auto mode then close the underlying serial port.

    Disabling auto mode before closing ensures the reader is left in a clean, command-driven state so the next session does not receive spurious EVN events or NAK responses from a lingering event mode.

    scan_tag ¶

    scan_tag() -> CardInfo

    One-shot card detection: REQUEST → ANTI_COLLISION → SELECT_CARD.

    Returns a CardInfo dataclass with the UID available in multiple representations. The card is left in the active state so you can immediately call authenticate_sector() / read_block() etc.

    Usage example:

    card = reader.scan_tag()

print(card.uid_int)    # 3989956803

    If no card is present or any step fails.

    wait_for_card_async async ¶

    wait_for_card_async(timeout: float = 10.0) -> str

    Async variant of wait_for_card. Does not block the event loop — serial I/O runs in a thread-pool executor.

    Suitable for use inside asyncio-based applications (FastAPI, Django async views, automation scripts using asyncio.run).

    Usage example:

    import asyncio
from mifarepy import MifareReader

async def main():
    with MifareReader('/dev/ttyUSB0') as reader:
        uid = await reader.wait_for_card_async(timeout=15)
        print('Card:', uid)

asyncio.run(main())

    authenticate_sector_cached ¶

    authenticate_sector_cached(sector: int, key_type: Literal['A', 'B'] = 'A', timeout: float = 1.0) -> None

    Authenticate a sector using a key that is already loaded in the reader.

    Skips the SAVE_KEY step (opcode 0x2B) and jumps straight to AUTHENTICATE_KEY (opcode 0x2E). This is faster when the same key has already been loaded by a previous authenticate_sector() call in the same session.

    Warning

    The reader only stores one key internally. If any other sector was authenticated (or the reader was reset) since the last SAVE_KEY, call authenticate_sector() instead.

    Parameters:

    Name Type Description Default
    sector int

    Sector to authenticate (0-15 for 1K; 0-39 for 4K).

    		 required
    key_type Literal['A', 'B']

    'A' for Key A (0x60) or 'B' for Key B (0x61).

    		 'A'
    timeout float

    Timeout in seconds for the reader response.

    		 1.0

    Raises:

    Type Description
    ValueError

    If key_type is invalid.
    GNetPlusError

    If the reader returns NAK.

    Card layout¶

    layout ¶

    MIFARE Classic memory-layout helpers.

    MIFARE Classic 1K has 16 sectors of 4 blocks. MIFARE Classic 4K has 40 sectors: 0-31 have 4 blocks each, 32-39 have 16 blocks each. The last block of every sector is its sector trailer (keys + access bits).

    Block numbers passed to MifareReader.read_block() / write_block() are relative to the authenticated sector; these helpers translate between relative and absolute numbering and tell you which blocks hold data.

    from mifarepy import layout

layout.blocks_in_sector(5)      # 4
layout.blocks_in_sector(35)     # 16
layout.data_blocks(35)          # range(0, 15)
layout.trailer_block(35)        # 15  (relative)
layout.absolute_block(35, 0)    # 176
layout.sector_of(176)           # (35, 0)
